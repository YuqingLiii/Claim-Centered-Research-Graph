## 2. Class B — check [5], one FAIL: a declaration, not a stub

`SE.goal` registers five routes; only `br` is formalized. Investigating the three options the
commission listed:

**(a) Do v6 routes carry their own `formalization`/lean state?** **No.** `proof_dag_v6.py`
`ROUTE_KEYS = {premises, assumptions, implication, proof, assessment, retired}`, closed-key
validated; `FORMALIZATION_KEYS = {lean}` exists only at node level. So a route cannot be marked
not-formalized in its own record without a schema change to a file `ksum` also depends on.

**(b) Should `ros` (REFUTED) count as a live route for this check?** **No — and this is a real tool
defect, fixed.** `DAG_PROTOCOL.md` §4: "A refuted premise disables every route that requires it."
`SE.ros` the NODE is REFUTED (the ROUTE implication is OPEN — the v6 migration correctly declined
to mirror premise failure into the implication). A disabled route is not an alternative anyone can
be asked to mirror in Lean. Check 7c of this very tool already excludes exactly these routes from
the epistemic floor; check 5 did not. I factored that predicate out (`route_disabled_reason`) and
now check 5 uses it too. The exclusion is **reported as INFO, never silent**:
`INFO [5] SE.goal: route(s) DISABLED per §4 ...: SE.ros (premise SE.ros is REFUTED)`.

**(c) A per-route not-formalized declaration.** Needed for `jz`, `mdh`, `sdp`, which are OPEN, not
disabled. Implemented as an entry in the EXISTING schema-v6 field `formalization.lean.rel` (no new
key, so `proof_dag_v6.py` closed-key validation is untouched):

```
route-not-formalized: <route-id> — <why no composition_via_* exists>
```

`SE.goal` now carries four such entries (`jz`, `mdh`, `sdp`, and `ros` for good measure — it is
covered twice, by the §4 exclusion and by an explicit declaration, so the record does not depend on
the tool's inference). Each states the actual reason: `proof: null` on the route, i.e. no prose
route proof exists to mirror, and for `jz` additionally that the multiplicative→`Adv±` transfer is
unproved, so a rendered theorem would resolve a VARIANT of the goal. **Zero stub theorems were
written.** `goal.lean`'s own ROUTE DECLARATION block (ruling R5, on disk since 2026-07-30) already
said all this in prose; the node now says it machine-readably, and `SE/Trust.lean` §D6/§D8 records
