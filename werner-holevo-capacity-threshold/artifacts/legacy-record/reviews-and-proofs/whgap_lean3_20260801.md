### Route deviations and one correction to the commission text — honest record

1. **The commission's route advice for `f_ge_sq` was factually wrong, and is corrected here.**
   It recommended "the StrictMonoOn derivative route that `f_pos` in private-boundary.lean
   already uses".  `f_pos` uses **no derivative at all**: it is the single-term Gibbs
   inequality `mul_log_gt` (`a - 1 < a log a`) applied twice.  There was no template to reuse,
   so the two-level `monotoneOn_of_deriv_nonneg` argument above was written from scratch.  The
   commission's own parenthetical ("or any sound route") covers this.
2. **Elementary (derivative-free) routes were tried on paper first and rejected**, and the
   reason is recorded in the module's append-only deviation record so that a later agent does
   not re-walk them: the Padé bound `log t ≥ 2(t-1)/(t+1)` (`t ≥ 1`) together with
   `log t ≥ (t - 1/t)/2` (`t ≤ 1`) gives only `f(s) ≥ s²/2 + s²/(2+s) < s²`; both one-sided
   bounds lose at order `s³`, whereas `f(s) - s² = s⁴/6 + O(s⁶)`.  `Real.log_le_sub_one_of_pos`
   alone gives only `f(s) ≥ 0` (= `f_pos`).  The inequality is tight Pinsker for a two-point
   distribution; no usable Pinsker inequality was found in Mathlib v4.31.0.
3. **The contraction identity `∑_μ A_μ X A_μᵀ = Tr(X)·𝟙 − Xᵀ` (paper `eq:kraus`) was dropped
   from the new module on build cost** after the first attempt timed out the kernel; it was a
   voluntary extra, not a commissioned item.  Only `A_transpose` remains as a standalone
   transcription check — but note that `lamCmin_eq_lamOne` is itself a sharp check of the same
   Levi-Civita table, since a mistranscribed `ε_{μjk}` would break it.
4. **`maxHeartbeats` is raised to `1000000` for the two entrywise `3×3` theorems** of the new
   module (`set_option ... in`, per declaration, not project-wide).  This is a resource knob,
   not a soundness knob; no `native_decide`, no `decide` on real-valued goals.

### Route substitution from the frozen commission — honest record

The commission froze this route: (1) sympy a rational kernel basis `K` (27×19) with
`V₅ᵀK = 0`, `V₃ᵀK = 0` plus an explicit rational `S⁻¹` for `S = [W₅ ∣ V₃ ∣ K]`; (2) `C S = S D`

**What was executed instead:** the WP-A decomposition
`C_x = (λ₅/12) W₅V₅ᵀ + (λ₃/16) V₃V₃ᵀ` **is already a rank-8 factorization** `C_x = F_x G`
through the eight-dimensional index type `Fin 5 ⊕ Fin 3`.  The *reversed* product `G F_x` is
8×8 and is diagonal by exactly the four small certificates already in the file.  Mathlib's
rectangular Weinstein–Aronszajn identity

    Matrix.charpoly_mul_comm_of_le (A : Matrix m n R) (B : Matrix n m R)
        (hle : Fintype.card n ≤ Fintype.card m) :
      (A * B).charpoly = X ^ (Fintype.card m - Fintype.card n) * (B * A).charpoly

then yields the result, and `Matrix.charpoly_fromBlocks_zero₁₂` + `Matrix.charpoly_diagonal`
finish the 8×8 side.  Consequences, stated plainly:

* **the expensive step does not exist any more.**  No kernel basis, no `S`, no `S⁻¹`, no
  27×27 product, nothing decided by `decide` beyond what WP-A already had.  The whole WP-E

  the incremental build), against the commission's ~8-minute allowance for step (3) alone.

  proves the identity where `S` diagonalizes `C_x`, i.e. it needs `x ≠ 0` (and the
  commissioned statement said "for all `x ≠ 0`").  The executed route gives it for **all real
